Before you spend

The Advisor only speaks up when it changes the decision: a saving of at least 15% and 100 credits, backed by enough history. Then graph8 enforces it through the list pipeline's own run condition.

NOT(EQ({{udo_roi_fit_11e946f0}}, "low"))
Tested live REAL

On a 3-contact list with one high-fit contact, graph8's own run record showed 1 enriched, 2 skipped, and the ledger charged 3 credits.

Why our own estimate

graph8's estimator ignores the run condition and "skip existing values", so it quoted 498 either way. The Advisor counts matching contacts through routing preview and prices them from the provider table.

Status

Registering an MCP server in graph8 works and shows up in workflows. graph8 only accepts SSE servers, so the Advisor serves SSE and streamable HTTP. A graph8 workflow calling our tools is build task 2.

Build plan

A thin working slice of every part in two days. The risky unknowns are tested first. Deeper work follows in the same order if time allows.

Day 1 · morning
  1. Next.js app on Vercel, password gate, graph8 SDK client with a 40/s rate limiter
  2. Webhook receiver deployed; capture real payloads from a [sim] deal and a workflow run RISK
  3. MCP server (SSE + HTTP); register in graph8 and call a tool from a workflow RISK
  4. Create the 5 custom objects and their fields
Day 1 · afternoon
  1. Ledger sync and attribution engine, tested against today's real ledger
  2. Run capture: pipeline runs, workflow events, spend through the Advisor
  3. Outcomes: deal history, engagement summaries, signed simulated events
  4. Findings and the surfacing rules
Day 2
  1. Dashboard: Overview, Charges, Recovery, Before you spend
  2. Guardrail flow on a real list
  3. Weekly recap to #roi-advisor on a Vercel cron
  4. Seed demo data, rehearse, clean up [sim] records
